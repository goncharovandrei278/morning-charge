## Объём MVP

- **7 дней** упражнений (один недельный цикл), не 28. Расширение до 4-недельного цикла — после подтверждения retention-гипотезы.
- **Голосовой режим сразу полноценный**: обратный отсчёт, объявление перехода между блоками, паузы — не урезанная версия "только название".
- **Стрик жёсткий**, без freeze/прощения пропущенного дня в MVP.

## 1. Модель контента дня и длительностей

Один упорядоченный список упражнений на день. У каждого упражнения в списке дня — тег `minDuration: 5 | 10 | 15`. Выбор длительности N берёт все упражнения с `minDuration <= N`, то есть 10-минутная версия — прогрессивное расширение 5-минутной, 15-минутная — расширение 10-минутной. Данные не дублируются между вариантами длительности.

Ориентир по объёму (не жёсткая формула, для планирования контента):
- 5 мин ≈ 6-7 блоков
- 10 мин ≈ 12-13 блоков
- 15 мин ≈ 18-20 блоков

(при среднем блоке ~40-45 сек работы + короткий отдых). Точный список упражнений и их порядок по дням прорабатывается отдельно, вне этого дизайна.

## 2. Единица упражнения

Поле `unit: "time" | "reps"` в записи упражнения.

- **time**: таймер обратного отсчёта, авто-переход к следующему блоку по истечении.
- **reps**: статичный экран с числом повторений, переход по кнопке/тапу "Готово" (без авто-перехода — точное число повторений браузер не измеряет).
- Для `reps`-упражнений дополнительно хранится `estimatedSeconds` — грубая оценка длительности, используется только при курировании контента (расстановке `minDuration` по дням), не участвует в работе таймера.

Медиа — поле-ссылка (`mediaUrl`) у каждого упражнения, не жёстко зашитый файл: на MVP — статичная картинка/иллюстрация, позже заменяется на WebP/WebM/MP4-loop без изменения схемы.

## 3. Воркаут-движок (таймер + голос + Wake Lock)

Хук `useWorkoutEngine`:

- **Таймер**: не аккумулирующий `setInterval`-счётчик, а `startedAt` + `pausedAccumMs` в `Date.now()`. `setInterval` тикает каждые ~250мс только для перерисовки UI; оставшееся время каждый раз пересчитывается из временных меток — сворачивание вкладки/блокировка экрана не сбивает отсчёт (устойчивость к фоновому режиму браузера).
- **Wake Lock**: запрашивается на старте тренировки, снимается на паузе/завершении/выходе. Браузеры автоматически гасят Wake Lock при уходе вкладки в фон и не восстанавливают его сами — нужен слушатель `visibilitychange`, перезапрашивающий лок при возврате на экран.
- **Голос**: обёртка над `SpeechSynthesis`-очередью — озвучивает смену упражнения, обратный отсчёт последних секунд, паузы между блоками. Отменяет все pending-фразы при досрочном пропуске/выходе, чтобы очередь не накапливалась. Экран — основной источник истины (название/прогресс/таймер всегда видны), голос — озвучка уже показанного; если `speechSynthesis` недоступен или заблокирован (частый случай на iOS без явного жеста пользователя), приложение просто молчит, весь UX остаётся рабочим через экран без отдельной fallback-логики.

## 4. Слой хранения и стрик

`exercises.json` и `programs/morning-charge.json` — статический контент, бандлится с приложением, в IndexedDB не хранится.

`storage.js` (единственная точка, знающая про Dexie) — две таблицы:

- **`completions`**: `{ date: "YYYY-MM-DD" (локальный календарный день пользователя, не UTC-таймстамп), duration, completedAt }`. Локальная дата-строка снимает необходимость таймзон-математики при подсчёте стрика.
- **`settings`**: `{ userId (uuid, генерится при первом запуске), defaultDuration, soundEnabled }`.

Публичный интерфейс: `getSettings()`, `saveSettings()`, `recordCompletion()`, `getStreak()`, `getCompletionsInRange()`. Когда дойдёт до Supabase-синка — меняется только этот файл.

**Стрик** считается на чтении (не хранится отдельным полем): идём назад от сегодняшней даты, пока дата есть в `completions`, инкрементируя счётчик. Если сегодняшнего дня в `completions` ещё нет — это не обрывает стрик (день не закончился), отсчёт просто начинается со вчерашней даты. Один пропущенный день сбрасывает счётчик в 0 (freeze не реализуется в MVP).

## 5. Экраны и навигация

**React Router**, 5 роутов: `/`, `/workout`, `/complete`, `/calendar`, `/settings`. Выбран вместо стейт-переключения экранов ради корректной семантики кнопки "назад" на Android/мобильных PWA (по умолчанию без роутера "назад" просто закрывает приложение). Во время тренировки навигация назад блокируется/требует подтверждения, чтобы случайный свайп не сбрасывал прогресс.

## Структура проекта

```
/src
  /data
    exercises.json
    programs/morning-charge.json
  /storage
    storage.js          // Dexie: completions, settings
  /hooks
    useWorkoutEngine.js  // таймер, wake lock, голос
    useStreak.js
  /components
    ExerciseCard, Timer, VoiceIndicator, ProgressCalendar, DurationPicker
  /screens
    Home, Workout, Complete, Calendar, Settings
  App.jsx               // роуты
```

## Вне рамок MVP (сознательно отложено)

AI, регистрация, соцфункции, подсчёт калорий, множество типов тренировок, 4-недельный цикл (28 дней), streak freeze, App Store/Google Play, детальная статистика сверх стрика и календаря — всё по решениям из исходного документа.

## Тестирование MVP

Бесплатный запуск на телефоне: во время разработки — `vite --host` по локальной сети (для HTTPS-зависимых фич типа Wake Lock — `mkcert` локально); для полноценного PWA-теста — деплой статики на Vercel/Netlify/GitHub Pages (бесплатный HTTPS), открыть ссылку на телефоне, "Добавить на экран Домой". Первые тестеры — сам + друзья/семья, распространение вручную.
